# 단순한 보고서 작성 흐름 — F-SIMPLE-WORKFLOW

작업일: 2026-10-02. 요청: 입력 항목이 눌리지 않는 문제를 고치고 복잡한 작동 방식을 최대한 단순하면서 유용하게 다시 설계한다. 기존 공식 출처·대회 정책·원본 보존·독립 출력 검사는 유지한다.

## 기본 사용

1. **HWPX 선택** 또는 **글 붙여넣기**로 시작한다. 붙여넣기는 ‘보고서로 만들 글’에 본문을 넣고 ‘이 글로 시작하기’를 누른다.
2. **대회와 문서 종류를 선택**한다. 기존 13개 유형/29개 작성 기준을 사용하며 기본값으로 시작할 수 있다. 파일명으로 채운 제목은 직접 수정한다.
3. **초안 만들기**를 누른다. 문단은 키워드 기반으로 추천 배치한다. 요약서를 고르면 포함 문단과 제외 확인을 먼저 선택한다.
4. 독립 검사를 통과한 **HWPX를 다운로드**한다. 실제 한글에서 최종 서식·쪽수·내용·제출 형식을 확인한다.

화면은 필수 행동을 먼저 보여주며 추가 설정을 모두 입력할 필요가 없다. 복잡한 설정을 기본 화면에서 접어도 기존 기능과 제한은 유지한다.

| 펼침 항목 | 확인·수정할 내용 |
| --- | --- |
| 세부 설정 | 학교급·기준 연도·작성 단계·표지 항목, 개인 참고 서식 |
| 문단 배치 확인·수정 | 원문 문단·자동 추천 역할·역할 수정·검색·긴 문단 탐색 |
| 질문을 보고 직접 내용 보완하기 | 실제 연구 내용을 직접 작성하고 포함 여부를 확인하는 보충 항목 |
| 공식 기준과 준비물 | 전국/지역 안내/전년도 출처, 공식 명시·해석·앱 기본값, 제출물·식별정보 확인 |
| 문서 검사 상세 | 작성 흐름 아래의 입력 검사 통계·문단·표·서식 구조 탐색 |

요약서의 문단 선택·제외 확인은 접힌 설정에 숨기지 않는다. 직접 보충한 내용도 입력만으로 추가하지 않으며 포함 동의 후 별도 집계한다. 준비 목록의 체크는 제출 완료나 연구 진위 확인이 아니다.

## 클릭 불가와 제한 안내

이전 화면은 초안을 생성할 수 있는지 판단한 값으로 입력 항목까지 잠갔다. 미지원 구조나 제한된 단계 때문에 생성이 막히면 사용자가 제목·단계·기준을 바꿔서 해결할 수도 없었다.

입력 가능 여부는 실제 처리 중인지로 판단한다. 검사·생성 중에는 중복 작업을 막으며, 처리 전후에는 생성 제한 상태에서도 기준과 입력을 수정할 수 있다. 생성 버튼은 필요한 조건이 충족된 경우만 활성화한다. 버튼 가까이에 제한 이유와 다음 행동을 표시하므로 추가 설정을 찾아 헤맬 필요가 없다.

이 변경은 대회 정책을 해제하지 않는다. 인성교육·EBS의 전국 단계 변경 금지, 학교급·연도·개인 참고값 검증, 미지원 객체 차단과 요약 선택 승인은 계속 적용한다. 단계 제한은 단계·기준 확인으로 안내하고, 표·그림 등 파일 구조의 제한은 원본 유지와 별도 글 입력을 안내한다.

## 글 붙여넣기와 새 작업

파일이 없거나 파일 구조 때문에 초안 생성이 어려우면 본문을 직접 붙여넣어 새 작업을 시작할 수 있다. 시작 화면의 ‘글 붙여넣기’와 제한 안내의 ‘글을 붙여넣어 새로 시작’은 같은 입력 경로를 연다.

이 경로는 **입력한 글만으로 새 원문 HWPX를 만드는 기능**이다. 업로드 파일의 내용을 자동으로 빼내지 않으며 파일의 표·사진·서식·기타 객체는 새 글 입력 문서에 보존되지 않는다. 한글 프로그램에서 줄글을 직접 복사할 수 있지만 HWP/PDF 변환이나 표·사진 이식 기능으로 설명하지 않는다. 기존 파일 작업을 교체할 때 새 작업임을 알리고 기존 원본·결과·검토 상태가 섞이지 않게 한다.

직접 입력한 문자열은 첫 비동기 처리 전에 복사한다. 빈 문자열·공백만 있는 글·표현 불가 문자·자원 제한 초과는 거부한다. LF로 나눈 각 줄을 하나의 문단으로 만들며 입력의 CR·탭·연속 공백·빈 줄·Unicode를 임의로 삭제하지 않는다. 새 HWPX는 실제 ZIP/XML로 생성하고 다시 열어 입력 문자열과 정확히 일치하는지 독립 비교한 뒤 기존 사전 검사·문서 읽기·초안 생성 엔진을 사용한다.

입력 상한은 **1,999줄·200만 문자**다. 새 패키지의 빈 설정 문단 한 개를 포함해 기존 2,000문단 상한을 유지한다. 원문과 다른 성공 응답, 지원 불가 문자를 조용히 제거한 결과, 실제 ZIP이 아닌 가짜 파일을 다운로드하지 않는다.

## 보존·개인정보·검수

파일 입력의 원본은 기존 바이트 동일 사본 다운로드를 유지하며 새 초안으로 덮어쓰지 않는다. 보고서는 모든 원문 문단을 정확히 한 번 옮긴다. 요약서는 사용자가 선택·확인한 문단만 그대로 옮기고 제외 수를 표시한다. 새 글 입력의 ‘원문’은 사용자가 입력한 문자열로 만든 새 문서이므로 기존 업로드 파일 보존과 별개다.

대회·제목·역할·세부 입력·요약 선택·보충 내용이 바뀌면 이전 출력은 무효화한다. 취소·오류·지연 응답에서는 부분 출력이나 다른 작업의 결과를 사용할 수 없다. 교체·종료·새로고침 시 문서와 검토 상태를 자동 복구했다고 표시하지 않는다.

입력·검사·생성·다운로드는 브라우저 메모리에서 처리한다. 앱과 Worker 준비 후 열린 화면에서의 오프라인 작업을 시험하며 오프라인 새 접속·새로고침까지 보장하지 않는다. 외부 AI·변환 서버·DB·지속 저장소·문서 전송을 추가하지 않는다. 개발·시험 자료는 합성 문서만 사용한다.

원본 읽기 모델은 `INSPECT_ONLY`, 원본 편집은 비활성이다. 복잡한 공식 표지·표·사진 이식·실제 쪽수·HWP/PDF 최종 저장은 지원 또는 검증 완료로 표시하지 않는다. **Windows 한컴 한글 개봉·조판·저장·재개방: NOT_RUN.** 생성 파일은 제출 적합성 인증이 아니라 작성 초안이다.
